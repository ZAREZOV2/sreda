# Среда — план будущих фич

> Записано 12.11.2026. Всё ниже одобрено Лукасом («понравились все»). Порядок — рекомендуемый, не жёсткий.

## 0. В работе сейчас
- Совместная работа через ngrok: хост на Rust (WebSocket), инвайт-ссылки с токеном, синхронизация операций с ревизиями, присутствие.
- «Узел закрыт»: сохранить копию локально или закрыть до следующего расшара.
- Переподключение: статический домен ngrok — та же ссылка; без него — новая ссылка, доска узнаётся по `workspaceId` + `hostId`.

## 1. Markdown-документы (офлайн)
Первый шаг реализован в разработке (0.2.2): раздел «Документы», отдельная таблица SQLite, создание и переименование, автосохранение через 700 мс, проверка ревизий, Markdown-исходник и безопасный GFM-предпросмотр, импорт/экспорт `.md` через системные диалоги. Закрытие окна и переход к доскам дожидаются записи; при ошибке черновик остаётся в редакторе и доступен для экспорта.

Это ещё не весь MVP: визуальный редактор, подсветка исходника/кода, папки, Markdown в карточках и FTS5 пока не реализованы. Документы пока локальные: не входят в совместную работу и JSON-бэкап досок; для переноса используется экспорт `.md`.

### Документы
- Раздел «Документы» в сайдбаре рядом с досками, папки.
- Привязка документа к карточке; описание карточки — полноценный md.
- Редактор с двумя режимами: визуальный (WYSIWYG, `**` сразу жирный) и исходный md с подсветкой; переключение одной кнопкой.
- Полный GFM: заголовки, списки, чекбоксы, таблицы, цитаты, код с подсветкой, ссылки, картинки, сноски, зачёркивание.
- Расширения: callouts `> [!NOTE]`, формулы KaTeX, диаграммы Mermaid.
- Чекбоксы `- [ ]` ↔ карточки на доске (в обе стороны).
- Внутренние ссылки `[[Документ]]` и `#карточка`, обратные ссылки.

### Файлы и офлайн
- Импорт/экспорт `.md`; режим «папка на диске» (как vault в Obsidian).
- Вставка картинок через Ctrl+V → вложения рядом с документом.
- Полнотекстовый поиск по документам и карточкам (SQLite FTS5).
- История версий документа с откатом (снимки + прореживание).
- Экспорт в HTML и PDF.

### Удобство
- Палитра команд Ctrl+K, меню блоков по `/`.
- Оглавление по заголовкам.
- Шаблоны: заметка со встречи, ТЗ, ретро.

### Стек
- CodeMirror 6 — исходный режим; Milkdown или TipTap с md-сериализацией — визуальный.
- Rust: `comrak` для GFM-валидации и рендера экспорта.
- Хранение в SQLite, файлы — только при экспорте или в режиме папки.

### MVP документов
1. Редактор с двумя режимами + полный GFM.
2. Импорт/экспорт `.md`.
3. md в описании карточек.
4. Поиск FTS5.

## 3. MCP-сервер для подключения ИИ
Цель: любой ИИ-клиент (Claude Desktop, Cursor, ChatGPT с MCP, локальные агенты) может читать и менять доски и документы «Среды».

### Транспорт
- stdio — встроенный бинарник `sreda-mcp`, ИИ-клиент запускает его сам (самый простой и безопасный вариант).
- Streamable HTTP на `127.0.0.1` — для клиентов, которым нужен URL; опционально через тот же ngrok-узел для удалённых агентов.
- Работает поверх тех же команд и валидации, что и UI; запись идёт через очередь ревизий, UI обновляется вживую.

### Инструменты (tools)
- Доски: `list_boards`, `get_board`, `create_board`.
- Карточки: `list_cards` (фильтры: колонка/тип, метка, приоритет, текст), `get_card`, `create_card`, `update_card`, `move_card`, `delete_card`.
- Колонки: `create_column`, `update_column` (включая тип todo/progress/done).
- Документы: `list_docs`, `read_doc`, `create_doc`, `update_doc` (md), `search` (FTS5).
- Связи: `link_doc_to_card`, `checklist_to_cards`.
- Resources: `sreda://board/{id}`, `sreda://doc/{id}` — для чтения как контекста.
- Prompts: «Разбей ТЗ на карточки», «Сделай ретро по доске», «Сводка за неделю».

### Настройки в приложении (экран «ИИ / MCP»)
- Вкл/выкл сервер, выбор транспорта (stdio / HTTP), порт.
- Режим доступа: только чтение / чтение и запись / запись с подтверждением в UI.
- Область: все доски или выбранные доски и папки документов.
- Токен доступа для HTTP (генерация, отзыв), список подключённых клиентов.
- Журнал действий ИИ с возможностью отменить изменение.
- Кнопка «Скопировать конфиг» с готовыми сниппетами для Claude Desktop / Cursor (`mcpServers` JSON), путь к бинарнику подставляется сам.
- Удаление через ИИ — всегда с подтверждением и через корзину/undo.

### Безопасность
- По умолчанию выключен и только чтение.
- HTTP слушает только localhost; наружу — только явно, с токеном.
- Лимиты размера запросов и частоты вызовов.

### Стек
- Rust: крейт `rmcp` (официальный Rust SDK для MCP), общий модуль с `storage.rs`.

## 4. Темы и нативная кастомизация
Цель: легко делать свои темы и делиться ими.

Сделано в этой сборке:
- **Всё на токенах.** Интерфейс берёт цвета, шрифты, тени и отступы из CSS-переменных бренд-набора (Golos Text, JetBrains Mono, знак «Узел»). Кольцо фокуса по-прежнему только `:focus-visible`, мягкий акцент.
- **Тема = один файл** `*.sreda-theme.json`: `name`, `author`, `version`, `base: dark|light`, `tokens`, необязательный `css`.
- **Стартовые темы:** Графит (тёмная по умолчанию), Бумага (светлая), Полярная ночь, Терминал.
- **Переключатель в интерфейсе** (кнопка «Тема»): живое применение на доске, выбор запоминается.
- **Импорт и экспорт** `*.sreda-theme.json`. Пользовательские темы хранятся в папке `themes/` каталога данных приложения (`%LOCALAPPDATA%\local.sreda.kanban\themes` в Windows). Доступ к папке — только узкими командами Tauri, без fs-плагина.
- **Безопасность:** схема + санитайзер на стороне приложения. Разрешены только известные токены; в значениях и в `css` отклоняются `url(`, `@import`, `javascript:`, `expression(`, теги и т.п. Недостающие токены берутся из базовой тёмной или светлой темы.

Ещё впереди:
- **Редактор тем в настройках:** «на основе текущей», пипетки, предупреждения по контрасту WCAG.
- Автоподхват при перетаскивании файла в окно; передача темы через совместную работу.
- Каталог тем.
